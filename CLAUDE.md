# CLAUDE.md

Guidance for Claude Code and other coding agents working in this repository. Human contributors: see [README.md](README.md) and [CONTRIBUTING.md](CONTRIBUTING.md).

## Project

Invoice Command is a free, open-source (AGPL-3.0) invoicing app hosted at invoicecommand.com: an invoice/estimate builder with live preview, voice dictation, PDF export, e-signatures, Stripe Connect payments, and 400+ profession template pages for SEO.

## Stack

- **Next.js 15** (App Router, Turbopack), React 19, TypeScript (strict)
- **Postgres** via **Drizzle**: schema in `src/lib/db/schema.ts`, client in `src/lib/db/index.ts`
- **Better Auth** (email + password, cookie sessions): `src/lib/auth.ts`, `src/lib/auth-client.ts`
- **Stripe Connect** (Express accounts) with an application fee per payment: `src/lib/stripe.ts`
- **Resend** for email, **OpenAI** for voice parsing (`src/app/api/parse-voice`)
- **Zustand** for builder state: `src/stores/invoice-store.ts` (anonymous drafts persist to localStorage)
- **Tailwind CSS v4 + shadcn/ui** (New York style) with the "Cool Money" theme
- **Sentry** for errors, **PostHog** and **Fathom** for analytics

## Commands

```bash
npm run dev        # http://localhost:3005
npm run build
npm run lint
npm test           # Jest (__tests__/)
npm run test:e2e   # e2e browser tests (tests/), see Testing
npm run db:push    # apply src/lib/db/schema.ts to DATABASE_URL
```

Environment variables are listed in the README.

## Layout

```
src/app/            routes; api/ for route handlers, api/v1/ for the public API (openapi.json)
src/components/     app components; ui/ holds shadcn components
src/data/           SEO page data: professions, purchase/sales order template clusters
src/content/blog/   blog posts (MDX)
src/lib/            db, auth, stripe, email, rate limiting, shared helpers
src/stores/         Zustand stores
packages/cli, packages/mcp   CLI and MCP server built on the v1 API
tests/              e2e tests; __tests__/ holds Jest tests
```

## Conventions

- Use the Cool Money theme tokens and shadcn/ui components; don't introduce another design system.
- Server Components by default; Client Components only when needed.
- Route handlers return 500s through `jsonErrorResponse` in `src/lib/error-response.ts`, which reports to Sentry.
- Escape user-controlled values in any HTML email, and validate outbound URLs (see `src/lib/webhook-service.ts`).
- The sitemap is generated by `src/app/sitemap.ts` from the same data as the pages. A new public route belongs there too.
- Profession pages come from `data/invoice-types.csv`: add a type with `node scripts/add-invoice-type.js <slug>`, which regenerates `src/data/professions-expanded.ts`.

## Do not break

- **Fathom analytics.** The `<Script src="https://cdn.usefathom.com/script.js" data-site="BQDNAWTT">` tag in `src/app/layout.tsx` must stay. It was once lost in a merge and a week of traffic data went missing. After editing the layout, check it with `grep -i fathom src/app/layout.tsx`.
- **Content Security Policy** in `next.config.ts`. A new third-party script, frame, worker, or API host needs a matching CSP entry, or it is silently blocked in production. `'unsafe-eval'` is added only under `next dev`.
- **Next.js 15 viewport.** Put `viewport` and `themeColor` in a separate `export const viewport`, not in `metadata`. In `metadata` they break manifest generation.

## Database (maintainers)

The hosted app uses **one Neon database for both development and production**. With the maintainer's `.env.local`, any migration or seed script you run locally is live on invoicecommand.com immediately. Don't run migrations until the change should be live, and delete any test rows you create. Contributors should point `DATABASE_URL` at their own database.

## Testing

- **Jest** covers libraries, hooks, stores, and components. Tests live in `__tests__/`, mirroring `src/`.
- **e2e** ([tester.army/e2e](https://tester.army/e2e)) drives a real browser. `e2e.config.ts` starts `npm run dev` itself. Agent steps (`agent.act`, `agent.assert`) call a model through the Vercel AI Gateway, so they need `AI_GATEWAY_API_KEY` or a `vercel link`ed project. Run `npx e2e guide` for the full reference.
- e2e tests must wait for hydration before typing (see `waitForHydration` in `tests/invoice-builder.e2e.ts`). Input typed into server-rendered HTML before React hydrates is silently dropped.
- `.e2e/` is excluded from Tailwind's source scanning in `globals.css`. Without that, e2e's output files trigger dev rebuilds that reset page state mid-test.
- CI runs both suites on every PR. Fork PRs don't receive secrets, so e2e skips there.

## Workflow

- Branch from `development` (`feature/123-…` or `fix/123-…`) and open PRs against `development`. Releases go from `development` to `main` by PR, and Vercel deploys `main` to production.
- `main` and `development` require the `jest` and `e2e` checks to pass.
- Keep commits small, one logical change each.
- First-time contributors sign the CLA through the bot on their PR.
